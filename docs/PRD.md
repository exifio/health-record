# PRD — 건강 기록 MVP

## 1. 문제

병원에 주기적으로 방문하는 사용자는 진료 시 최근 며칠 또는 몇 주의 상태 변화를 정확히 기억해 설명하기 어렵습니다. 이 서비스는 사용자가 평소 건강 상태를 자연어로 남기고, 이후 그 기록을 날짜별로 다시 확인할 수 있게 하여 기억 의존도를 낮춥니다.

## 2. 제품 목표

### 핵심 목표

- 사용자가 하루 동안의 건강 상태를 부담 없이 기록한다.
- 사용자 원문을 그대로 보존한다.
- 하루 종료 후 AI가 원문을 시간 흐름 중심으로 구조화한다.
- 사용자가 AI 초안을 직접 확인·수정한 뒤 확정한다.
- 진료 전 선택한 기간의 **확정 기록만** 날짜별로 보여준다.

### 비목표

- 진단
- 질병 가능성 분석
- 원인 추정
- 치료 방법 또는 약 추천
- 다일 패턴 분석
- 의사용 EMR/차트 대체
- 의료기관 시스템 연동

## 3. 핵심 사용자 흐름

```text
비로그인 진입
→ 실제 서비스 형태 + 로그인 모달
→ 둘러보기 또는 Google 로그인
→ 오늘 기록 작성
→ 원문 DB 저장
→ 필요할 때 비강제 보완 제안 표시
→ 하루 종료
→ AI 자동 정리 초안 생성
→ 다음 접속 시 '확인 필요' 표시
→ 사용자 확인/수정
→ 확정
→ 진료 준비에서 기간 선택
→ 확정된 날짜별 기록만 시간순 표시
```

## 4. 제품 정책

### 4.1 원문 우선

- `record_messages`가 원본입니다.
- AI 요약은 원본을 대체하지 않습니다.
- AI 결과에서 원문에 없는 사실을 추가해서는 안 됩니다.

### 4.2 하루 기준

- 하루는 기록 시점의 **기기/브라우저 시스템 시간 기준 `00:00~23:59`**입니다.
- 사용자가 timezone을 직접 선택하거나 관리하는 기능은 제공하지 않습니다.
- Client는 시스템의 IANA timezone을 자동 감지해 서버에 metadata로 전달합니다.
- 서버는 새 daily record 생성 시 해당 timezone을 내부 snapshot으로 저장하고 `local_date`를 고정합니다.
- `created_at`은 UTC로 저장하되, 이미 결정된 과거 `local_date`는 이후 시스템 timezone이 바뀌어도 재계산하지 않습니다.

### 4.3 자동 정리

- 사용자가 매일 버튼을 눌러 정리하지 않습니다.
- 날짜 종료 후 스케줄 작업이 미확정 일일 기록을 찾아 요약합니다.
- 정확히 00:00 실행할 필요는 없습니다.
- 요약 작업 실패 시 원문은 그대로 보존됩니다.

### 4.4 AI 보완 제안

- AI는 사용자와 대화하지 않습니다.
- 제안은 최대 2~3개이며 답변을 강제하지 않습니다.
- 충분한 정보가 있으면 제안하지 않습니다.
- 제안 예시: 발생 시점, 지속 시간, 사용자가 느낀 정도, 복약 여부/이름/시간, 복용 후 상태 변화.
- UI에서는 'AI 답변' 말풍선이 아니라 선택적 보완 카드/힌트로 보입니다.

### 4.5 확정 전 수정

사용자는 미확정 기록의 메시지를 추가/수정/삭제할 수 있습니다.

중요: AI 초안 생성 후 원문이 바뀌면 기존 초안은 더 이상 최신 원문을 반영하지 않습니다. 따라서:

1. 원문 변경 시 `content_revision` 증가
2. 기존 요약을 `stale`로 표시
3. 재요약 대기 상태로 전환
4. 최신 revision으로 생성된 요약만 확정 가능

### 4.6 확정

- 사용자가 AI 정리를 확인한 뒤 확정합니다.
- AI 초안을 그대로 승인하거나 사용자가 직접 수정한 최종 정리를 승인할 수 있습니다.
- 확정 후 기존 원문과 확정 요약은 일반 수정 경로에서 변경하지 않습니다.

### 4.7 확정 후 정정

- 과거 확정 기록의 메시지를 덮어쓰지 않습니다.
- 잘못된 사실을 발견하면 `corrections`에 새로운 정정 기록을 추가합니다.
- 진료 준비에서는 원래 확정 요약과 정정 기록을 함께 확인할 수 있어야 합니다.
- 정정은 기존 사실을 기술적으로 삭제하거나 교체하지 않습니다.

### 4.8 하루 전체 삭제

사용자는 특정 날짜 전체 기록을 삭제할 수 있습니다.

삭제 범위:
- 원문 메시지
- AI 초안/사용자 최종 요약
- 보완 제안
- 정정 기록
- 관련 파생 데이터

MVP에서는 앱 DB에서 실제 삭제(hard delete)를 수행하는 방향을 기본으로 합니다. 백업·인프라 수준 보존 정책은 사용하는 서비스의 실제 정책을 별도로 확인하고 개인정보 처리 안내에 반영해야 합니다.

### 4.9 진료 준비

- 사용자가 기간을 선택합니다.
- 확정된 기록만 기본 포함합니다.
- 기록이 없는 날짜는 아예 표시하지 않습니다.
- 미확정 날짜가 있으면 개수를 알려주고 `기록 확인하기` 또는 `확인된 기록만 계속하기`를 제공합니다.
- 다일 AI 분석은 하지 않습니다.
- '최근 한 달 동안 반복적으로...' 같은 새로운 패턴 결론을 만들지 않습니다.

## 5. 로그인/비로그인

### 비로그인

- 실제 서비스 UI를 배경으로 로그인 모달 표시
- `둘러보기` 가능
- 샘플 오늘 기록/과거 기록/AI 요약/진료 준비를 확인 가능
- 실제 건강정보 입력은 금지
- 입력 시도 시 로그인 모달 표시

### 로그인

- Google 로그인 지원
- Kakao는 `준비 중`
- 로그인 직후 첫 사용자에게 짧은 사용 안내 표시

## 6. 상태 모델

DB에서는 UI 상태를 한 개 enum으로 모두 표현하지 않고 다음처럼 분리합니다.

### record_status

- `draft`: 아직 사용자가 확정하지 않음
- `confirmed`: 사용자 확정 완료

### summary_status

- `not_due`: 아직 해당 날짜가 끝나지 않음
- `pending`: 요약 생성 대기
- `processing`: 생성 중
- `ready`: 최신 원문 revision에 대한 초안 생성 완료
- `stale`: 초안 생성 후 원문이 변경됨
- `failed`: 최근 요약 시도 실패

### UI 표시 상태

| 조건 | UI 문구 |
|---|---|
| draft + not_due | 작성 중 |
| draft + pending | AI 정리 대기 |
| draft + processing | AI 정리 중 |
| draft + ready | 확인 필요 |
| draft + stale | 다시 정리 중/정리 필요 |
| draft + failed | 정리 실패 |
| confirmed | 확정 |

## 7. MVP 기능 요구사항

### 오늘 기록
- 여러 메시지 추가
- 시간 표시
- 확정 전 수정/삭제
- AI 비대화형 보완 제안

### 기록 확인
- 날짜별 목록
- 미확정 개수 표시
- 날짜 상세에서 원문과 AI 요약 확인
- AI 요약 직접 수정
- 확정
- 확정 후 정정 기록 추가

### 진료 준비
- 기간 선택
- 확정 기록만 날짜별 표시
- 기록 없는 날짜 숨김
- 미확정 기록 경고
- 날짜 클릭 시 원문 확인

### 설정
- 화면 테마 선택: `시스템 설정 / 라이트 / 다크`
- 기본 테마는 `시스템 설정`을 따름
- 테마 선택은 건강 데이터와 분리된 UI 환경설정으로 취급
- 전체 건강 기록 삭제
- 계정 삭제
- 개인정보/AI 처리 안내 링크
