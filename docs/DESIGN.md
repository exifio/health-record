# DESIGN — UX/UI 설계

## 1. UX 원칙

1. 기록 화면은 채팅처럼 편하지만 AI 대화 서비스처럼 보이지 않아야 합니다.
2. 사용자의 입력이 항상 중심이며 AI는 보조 정보로만 나타납니다.
3. 로그인 전에 실제 건강정보를 입력하게 만들지 않습니다.
4. AI 결과는 과도하게 경고하지 않되 '확인이 필요한 초안'임을 명확히 표시합니다.
5. 모바일 퍼스트로 설계하고 데스크톱에서는 사이드패널을 활용합니다.
6. 상태 용어는 의료 전문용어보다 행동 중심으로 씁니다.

## 2. 전체 정보 구조

### 사이드패널

```text
오늘 기록
진료 준비

최근 기록
- 9월 25일  [확인 필요]
- 9월 24일  [확정]
- 9월 22일  [확정]

모든 기록 보기

----------------
설정
사용자 프로필
```

- 데스크톱/모바일 모두 펼치기·접기 지원
- 모바일에서는 오버레이 패널 형태 허용
- 별도 모바일 하단 탭은 만들지 않음

## 3. 비로그인 진입

### 최초 화면

- 실제 앱 레이아웃을 배경으로 렌더링
- 중앙에 로그인 모달

모달:
- 서비스 한 문장 설명
- `Google로 계속하기`
- `둘러보기`
- `Kakao 로그인 — 준비 중`

### 둘러보기

- 실제 DB가 아닌 정적 샘플 데이터 사용
- 샘플임을 상단에 명확히 표시
- 사용자가 입력창에 타이핑하기 전 또는 제출 시점에 로그인 필요를 안내
- 실제 텍스트가 서버로 전송되지 않도록 제출을 막음

## 4. 온보딩

로그인 후 첫 진입 시 작은 안내 카드 또는 모달을 1회 표시합니다.

> 오늘 있었던 건강 상태를 편하게 남겨보세요.  
> 예: 아침부터 머리가 조금 아팠어요 / 점심에 약을 먹었어요 / 저녁에는 괜찮아졌어요.  
> 의료 용어를 사용할 필요는 없습니다.

복잡한 단계형 튜토리얼은 만들지 않습니다.

## 5. 오늘 기록 화면

### 기본 구성

1. 페이지 제목: `오늘 기록`
2. 현재 날짜
3. 오늘의 메시지 타임라인
4. 필요할 때만 보완 제안 카드
5. 하단 입력 영역

### 메시지 표현

- 사용자 입력만 메시지 버블로 표시
- AI 답변 버블 없음
- 각 메시지에 작성 시간 표시
- 미확정 상태에서 수정/삭제 메뉴 제공

### 입력 영역

- 한 줄 입력에서 시작해 내용에 따라 확장
- 전송 버튼
- 건강상담/진단 질문을 유도하는 placeholder를 쓰지 않음
- 예: `오늘 있었던 상태를 기록해보세요`

### 보완 제안

말풍선 대신 아래 형태를 사용합니다.

```text
기록을 더 남기고 싶다면
- 언제쯤 시작되었는지 기록할 수 있어요.
- 얼마나 지속되었는지 기록할 수 있어요.
```

- 최대 2~3개
- `답변하기` 강제 없음
- `닫기` 가능
- 충분한 기록이면 영역 자체를 표시하지 않음

## 6. 과거 날짜 상세

### 미확정 + AI 요약 준비 완료

```text
9월 25일 기록을 정리했어요
[확인 필요]

정리된 내용
- ...
- ...

더 남겨두면 좋은 정보
- ...

AI가 작성한 정리는 실제 기록과 다를 수 있습니다.
저장 전에 내용을 확인해주세요.

[정리 내용 수정] [확정]

원문 기록 보기
```

### 수정

- AI 정리 결과를 텍스트/항목 단위로 편집
- 원문 수정과 AI 요약 수정은 UI상 구분
- 원문이 바뀌면 기존 AI 요약은 즉시 '최신 원문과 다름' 상태로 전환
- 재요약 완료 전 확정 버튼 비활성화

### 확정 후

- 원문 수정/삭제 메뉴 숨김
- `정정 기록 추가` 제공
- 날짜 전체 삭제는 별도 위험 작업 메뉴에 유지

## 7. 미확인 기록 알림

접속할 때마다 모달을 반복하지 않습니다.

사이드바 또는 오늘 기록 상단에:

> 확인하지 않은 기록이 3개 있습니다. [확인하기]

- 클릭 시 오래된 날짜부터 또는 최신 날짜부터 목록으로 이동
- 사용자에게 강제하지 않음

## 8. 진료 준비

### 입력

- 시작일
- 종료일
- `기록 불러오기`

### 미확정 포함 기간

> 선택한 기간에 확인하지 않은 기록이 2개 있습니다.

버튼:
- `기록 확인하기`
- `확인된 기록만 계속하기`

### 결과

날짜별 카드:

```text
9월 2일
- 오전부터 두통이 있었음
- 오후 1시경 약을 복용함
- 이후 상태가 완화됨
[원문 보기]
```

- 기록 없는 날짜는 렌더링하지 않음
- 다일 패턴/추세 문구 없음
- 그래프 없음
- 정정 기록이 있다면 해당 날짜 하단에 별도 `정정 기록` 섹션 표시

## 9. 모든 기록 보기

- 날짜 내림차순
- 상태 badge 표시: 작성 중 / 정리 중 / 확인 필요 / 확정 / 정리 실패
- 검색, 질환별 필터, 고급 필터는 MVP 제외

## 10. 설정

### 계정
- 로그인 제공자
- 프로필

### 날짜와 시간
- 사용자에게 timezone 선택/표시 UI를 제공하지 않습니다.
- 오늘 날짜와 기록 시간은 사용 중인 기기/브라우저의 시스템 날짜·시간을 자동으로 따릅니다.
- 하루 시작 시간을 사용자가 변경하는 기능은 제공하지 않습니다.

### 화면 테마
- `시스템 설정`, `라이트`, `다크` 3가지 선택지를 제공합니다.
- 기본값은 `시스템 설정`이며 OS/브라우저의 `prefers-color-scheme`을 따릅니다.
- 사용자가 라이트 또는 다크를 직접 선택하면 해당 브라우저에서 선택을 유지합니다.
- 로그인 전 화면, Demo Mode, 로그인 모달, 실제 서비스 화면에 같은 테마 규칙을 적용합니다.
- MVP에서는 테마 설정을 건강 기록이나 사용자 프로필 DB에 저장하지 않고 브라우저 UI 설정으로만 관리합니다.

다크모드 디자인 원칙:
- 단순히 흰색과 검은색을 반전하지 않고 배경/표면/텍스트/경계선/상태 색상을 semantic token으로 관리합니다.
- 긴 건강 기록을 읽기 편하도록 본문과 배경의 대비를 충분히 확보합니다.
- 비활성 상태, AI 안내, placeholder가 다크모드에서 지나치게 흐려지지 않게 합니다.
- 상태 badge와 오류/위험 UI는 색상만으로 의미를 전달하지 않습니다.
- 사용자 건강 기록 내용을 장식적인 색상으로 강조하지 않습니다.

### 데이터
- 특정 날짜 전체 삭제: 날짜 상세에서 제공
- 모든 건강 기록 삭제
- 계정 삭제

위험 작업은 확인 모달을 사용합니다.

## 11. 반응형

### 모바일
- 1열
- 입력 영역은 화면 하단 접근성이 좋도록 배치
- 사이드패널은 오버레이
- 진료 준비 날짜 카드도 1열

### 데스크톱
- 접을 수 있는 좌측 사이드패널
- 본문 최대 폭을 제한해 긴 문장이 지나치게 넓어지지 않게 함
- 모바일 구조를 억지로 중앙의 작은 휴대폰 폭으로 고정하지 않음

## 12. 오류 UX

### 원문 저장 실패

> 기록을 저장하지 못했습니다. 다시 시도해주세요.

AI 문구를 표시하지 않습니다.

### AI 정리 실패

> 기록 정리를 완료하지 못했습니다. 작성한 기록은 정상적으로 저장되어 있습니다.

`다시 정리하기`

### 보완 제안 실패

- 기록 저장 성공을 유지
- 제안 영역만 표시하지 않거나 재시도 가능
- 전역 오류 토스트로 과도하게 강조하지 않음
